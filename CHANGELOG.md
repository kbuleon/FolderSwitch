History of **software changes** to the project's programs. Changes that only create `docs` files are not tracked here.
This file is maintained by the agent. The log is timestamped and **concise**. It is not documentation.

------

## 2026-11-03

* **1.9.0 — Updates from GitHub releases** (FOS-0011): installed copies look for updates in the GitHub releases of `kbuleon/FolderSwitch` (stable ones, no token) instead of a feed folder; the `localhost` test address is gone, and any address that is not that of a GitHub repository turns the check off. A « Check for updates automatically » box in the settings, ticked by default, unticked stops the automatic checks (the first one a minute after the start, then daily) at once, without a restart (the « Check for updates » button still works, and an import brings its value); the configuration stays schema 2, and a 1.8.0 ignores the setting. `build/release.ps1` (`Prepare`, `Publish`, `All`) tests, tags `v<version>` and publishes a release with the `CHANGELOG.md` entry as notes; `pack.ps1 -ReleaseNotes`. Nine languages.

## 2026-11-02

* **1.8.0 — Emoji icons for tabs and groups** (FOS-0010): a tab and a group can show an emoji to the left of their name, drawn in one colour, the text's, in « Segoe UI Emoji ». The icon is given from the name when it is typed, at creation and at each rename (the first-run content too, never « New tab » nor « New group »): from FolderSwitch's own table of common folder and site words, then from the Unicode (CLDR) keywords of the current language, then English's; none when no word leads to an emoji. In Edit mode a click on the icon (or on its empty slot), or « Icon… » in the right-click menu, opens a picker: a filter on keywords, « Automatic », « No icon » and the categories. An icon chosen by hand never changes on a rename; existing tabs and groups are given none. An icon the machine's emoji font cannot draw is hidden and kept in the configuration. Emoji data (781 emojis, Unicode Emoji 18.0 and CLDR 49, nine languages) made by the new `tools/FolderSwitch.EmojiData`, shipped in `Emoji\` next to the executable and loaded in the background, never fetched; under the Unicode License v3 (`THIRD-PARTY-NOTICES.txt`, `REUSE.toml`). Configuration schema stays 2 (`icon`, `iconChosen`); a 1.7.0 reads the file, ignores the icons and drops them when it saves. Nine languages.

* **1.7.0 — GPL-3.0-or-later license** (FOS-0007): FolderSwitch is free software under the GPL-3.0-or-later, Copyright (C) 2026 Karl BULEON, with additional terms (section 7): attribution kept, no « FolderSwitch » name nor icon for a modified version, no trademark right. `LICENSE` (the GPLv3 text), `THIRD-PARTY-NOTICES.txt` (MIT notices of the packages and runtimes; a pointer for Velopack's Rust crates), `REUSE.toml`, `CONTRIBUTING.md` (no code contributions) and a « License » section in the README. Every `.cs`, `.xaml` and `.ps1` file starts with an SPDX header; a C# file without it fails the build (IDE0073). The About window has a shorter description and shows the copyright, the license and the absence of warranty, with links to `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt`, now installed next to `FolderSwitch.exe`; nine languages. The executable's properties show the copyright.

* **1.6.0 — Current URL checked before it is added** (FOS-0009): « Current URL » in the Add menu no longer adds the page at once; it opens the « URL… » prompt with the page's address, which can be edited (to remove a session id, say) before it is added, still named by the page's title. Cancelling adds nothing. The menu's tip says so, in nine languages.

## 2026-11-01

* **1.5.0 — Web sites, file type icons and the Add menu** (FOS-0004): a third kind of item, the web site, next to the folder and the file: it opens in the default browser, and its right-click menu offers « Copy address ». A group has one « Add ▾ » button in place of « + Folder », « + File » and « + Current folder »; its menu starts with what the calling window shows, « Current folder » from Explorer or a file dialog, « Current URL » from Firefox, Chrome or Edge (read through UI Automation while the menu is open, retried for 2 s, no extension), then « Folder… », « Special folders », « File… » and « URL… » (a prompt that starts with the clipboard's address), and ends with a line that says where FolderSwitch was called from. A file shows the icon Windows gives its type, found without touching the file; a site shows its favicon, fetched in the background into `%APPDATA%\FolderSwitch\favicons` (5 s, 256 KiB, no cookie, `User-Agent: FolderSwitch/<version>`; one more try per session for a site missing from the cache), the globe meanwhile. Called from a file dialog, files and sites are greyed out with a tooltip, and a file no longer moves the dialog to its folder; the context line at the bottom of the window is gone. Configuration schema 2 (`url` items): a version 1 file is read as is, a previous FolderSwitch sets a version 2 file aside. The update feed is no longer the only host contacted. Nine languages.
* **1.4.0 — Installation and update message in a box**: the message shown once an installation, a repair (the installer run again) or an update ends is now a message box, read at the user's pace, instead of a notification that disappears; it comes before the other startup messages. A first installation shows it too, after the wizard, in place of the ready notification, which remains only for a first run without an installation.
* **1.3.0 — Notification after an installation or an update**: the installer and the updater end without a word; FolderSwitch now says, once ready, « FolderSwitch has been updated to version x.y.z » or « FolderSwitch x.y.z has been installed », then « Press Ctrl + ⊞ Win to open FolderSwitch » (the shortcut in effect, left out when it could not be registered). A first installation keeps the wizard's ready notification only. From Velopack's first-run and restarted hooks; nine languages.
* **1.2.0 — Drag and drop to another tab; Edit-mode right-click menu**: in Edit mode, a column, a group or an item dragged onto another tab and held there for half a second shows that tab, where it can be dropped anywhere (an item needs a group); a drag that drops nothing goes back to its tab. A tab keeps at least one column: the last one has no ✕ and cannot be dragged out, and a tab without a column, from an older configuration, gets an empty one when loaded. A right-click on a tab, a group's header or an item, in Edit mode, opens a menu with « Rename » (F2); tabs lose their selection frame (the underline already marks the tab shown) and F2 without a selection renames the tab shown. The window keeps the width of its widest tab, so the tabs no longer move when another one is shown; only the height follows the tab. A column fits its content again after a change of theme.

## 2026-10-31

* **1.1.0 — Columns move by drag and drop**: in Edit mode, each column has a ⠿ grip on the middle of its top edge; dragging it moves the column, with its groups and its width, within its tab (an insertion line shows where). Edit mode leaves room above the columns, so the grip, the ✕ of an empty column and the width being dragged are no longer cut off at the top.
* **1.0.0 — First stable version; item menu and version in the title** (FOS-0003): a right-click on an item, in normal use, opens a menu: « Open in File Explorer » (a new window; for a file, « Open file location », its folder) and « Open in new tab » with « Ctrl+click », only when a Ctrl+click opens a tab (a folder, called from Explorer, Windows 11). The title bar shows the version after « FolderSwitch ».
* **0.2.1 — Fix: Ctrl+click opened a stray window**: the new tab stayed on Home and the folder opened in a new Explorer window when Ctrl was still held at the navigation; the new tab is now navigated with `IShellBrowser.BrowseObject` (same browser), which ignores Ctrl. Title bar buttons share one height.
* **0.2.0 — Settings in one window** (FOS-0002): ⚙ and (?) always in the title bar; one settings window drawn over the main window on a dimmed backdrop, with categories (General, Shortcut, Appearance, Configuration) and ✕ / Escape / backdrop click to close; the separate appearance button is gone. « Apply » is disabled while the shortcut shown is the one in effect, with a « ✓ This shortcut is active » note; a shortcut refused at startup can be applied again. New About window. The shortcut goes to the test zone only on the Shortcut page.
* **« Customize » becomes « Edit »** (FOS-0002): « Modifier » in French, in the nine languages, tray menu included; title bar order « Edit », ⚙, (?), ✕; messages that sent the user to « Customize mode » for the settings now point to the settings.
* **Version in the repository**: `<Version>` property in `Directory.Build.props` (0.1.1, the last release); `build/pack.ps1` releases it by default, `-Version` now optional.

Customize mode with drag and drop, 7 themes, 9 languages, first-run wizard, JSON configuration with backups, notification-area icon, Velopack installer and updates, `--self-test` and `--snapshot` modes.
